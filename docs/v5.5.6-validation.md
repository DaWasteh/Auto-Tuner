# AutoTuner v5.5.6 validation

Local checks: **2026-09-24**, Windows x64, Python **3.14.5**, Core Ultra 9
285K, RX 9070 XT and Radeon AI PRO R9700. Both user-built mainline runtimes
are **b11160 / 70c4e1582** (`0.5.0-dev`). See the
[upstream audit](llama-b11160-audit.md) and
[CLI/binary manifest](llama-b11160-server-flags.json). No existing llama
runtime or fork was modified and no foreign process was stopped.

## Start minimized after login

- The login entry now carries `--autostart` (Windows HKCU Run, XDG
  autostart, macOS LaunchAgent). Only an entry that exactly matches the
  running installation's pre-v5.5.6 command is upgraded on start; entries of
  another copy stay untouched. On this machine the first start of the rebuilt
  `dist/AutoTuner.exe` changed the real Run value from
  `"L:\GitHub\Auto Tuner\dist\AutoTuner.exe"` to
  `"L:\GitHub\Auto Tuner\dist\AutoTuner.exe" --autostart`.
- The new setting follows *Hide on close* until the user saves a choice;
  login start → tray (Hide on close + tray available) or minimized taskbar
  window; manual starts are never affected; a duplicate login start exits
  quietly instead of raising the running window.
- Unit tests (`test_login_start.py`, 11): setting fallback/override,
  Windows/Linux/macOS upgrade and non-hijacking, all window-mode branches,
  tray start + restore with the deferred native icon/system-menu setup, and
  the dialog's mirror/explicit behaviour. Existing autostart and hover-help
  tests were extended; all nine packs translate the label and both tooltip
  levels.
- Real desktop processes (opt-in `test_single_instance.py`), from source and
  against the frozen EXE: **4 passed** each — close/exit, second launch
  restoring a tray-hidden instance, **login start stays window-less for 8 s
  and is restored by a second launch**, and **login start without Hide on
  close is minimized** (`IsIconic`).

## Vulkan int8 cooperative matrix (PR #27952) on the R9700

`llama-bench` on `Vulkan1` (R9700), `-ngl 99 -fa 1 -r 3`, Qwen3.8-27B dense
quants, b11159 (last tag before #27952) against b11160, ABBA order per quant:

| Quant | Test | b11159 | b11160 | Δ |
|---|---|---:|---:|---:|
| Q8_0 | pp512 | 771.6 | 883.9 | **+14.6 %** |
| Q8_0 | pp2048 | 864.5 | 978.6 | **+13.2 %** |
| Q8_0 | tg128 | 19.7 | 19.9 | +0.8 % |
| IQ4_XS | pp512 / pp2048 / tg128 | 804.3 / 798.9 / 35.0 | 801.8 / 796.6 / 35.1 | ±0.3 % |
| UD-Q4_K_XL | pp512 / pp2048 / tg128 | 785.8 / 788.7 / 31.0 | 799.7 / 790.9 / 30.9 | +1.8 / +0.3 / −0.1 % |

Prompt processing on Q8_0 gains ~14 %; the Q4_K-based UD quant stays on the
FP16 path by design, and IQ4_XS shows no measurable change on this card.
Token generation is unaffected (matrix-vector kernels). The path is active
by default; AutoTuner needs no setting.

**Measurement hygiene:** a first attempt overlapped a Voice Lab
Whisper/TTS job from another session on the same GPUs and was discarded
(it showed a spurious −80 % for b11160). The final run refused to start while
such jobs ran and checked that the R9700 had the model size plus margin free
before every run; the other session paused new GPU work for the window. The
first b11159 Q8_0 pass of the final run (68.6 t/s pp512, directly after that
overlap) is excluded as an outlier; the b11159 Q8_0 values above are the mean
of the clean first-attempt run and the final ABBA run, which agree within 3 %.
ComfyUI stayed resident but idle throughout.

## Stable v0.5.0 recipe run

To prove the unchanged recipes against the new minor version, the stable
Vulkan and HIP recipes were run with `-Tag v0.5.0` into new folders
`0.5.0_{vulkan,hip}_llama.cpp` (existing trees untouched). Both verified tag,
commit **7fe450e19**, compatibility build **b11146** (= the pre-release tag
of the same commit), runtime version `0.5.0` (`LLAMA_BUILD_IS_DEV=OFF`),
backend-exclusive device lists with both cards, and on HIP the no-peer-copy
cache bit plus the two-GPU layer split decoding exactly `HIP MULTI GPU OK`.
AutoTuner probes both binaries as b11146 and their 415 flags equal b11160's.
The HIP compile shows the usual `-Wpass-failed` occupancy diagnostics in
flash-attention tile kernels (not suppressed by policy, not errors).
