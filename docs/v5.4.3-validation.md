These are not an exhaustive performance comparison, a Q4/Q8 accuracy study,

placement, not actual CUDA/Metal inference on this Windows machine.

## Important regressions covered

- Q8 ceiling even with surplus memory and obsolete profile hints; explicit
  F16/BF16 pins remain authoritative.
- Q4 capacity fallback, per-slot budgets, one-sided K/V pins with unequal head
  dimensions, and actual pin/compatibility precision in placement reserves.
- Non-FA/Grok/unaligned-head F16 exceptions; legacy saved FA choices recascade.
- Manual snapshot KV byte estimates rescale separate K and V costs, context
  and slot count, without quantising recurrent state.
- Qwen4exp reconsiders Q8 after its host/QSA context clamp; physical pool limits
  remain binding. Dense partial offload does not reopen exhausted GPU peers.
- Mainline diffusion CLI emits its planned KV types and FA state;
  DiffusionGemma retains the separate forced-F16 runner contract.
- Unsupported cache controls cannot silently disappear into larger runtime
  defaults; optional n-gram controls prune their values correctly.
- HY4 mainline versus patched GGUF metadata, Spark profile/build gate, all
  profile flags, translated notes, and benchmark search-schema invalidation.

## Performance dashboard / Pages

The existing public dashboard contains substantially more historical evidence
than the current local database (the latter exports only 12 saved runs across
3 models). Re-exporting it wholesale would discard published measurements.
Instead, this release adds an explicit Q8-policy/historical-results notice to
the existing HTML and the report generator. Removing that notice reproduces
the prior committed HTML exactly: **no measurement, setting, timestamp or
provenance was relabelled or dropped**. CSP/path-redaction validation passes.

The changed `benchmark-site/index.html` triggers the existing Pages deployment.
No full new hardware benchmark sweep was represented as having run.

## Remote publication gates

Main must pass the existing Windows/Linux/macOS Python 3.10–3.14 matrix, Ruff,
and six additional Linux distro source jobs **before tagging**. The v5.4.3 tag
then builds Windows x64, Linux x64 and macOS arm64 ZIPs; frozen smokes and the
seven Linux-distro binary launches precede publication. The operator verifies
the public release, exact tag commit, downloaded executable architectures and
GitHub asset SHA-256 digests after that workflow succeeds. Remote job results
are recorded in GitHub Actions and the release notes, rather than predicted by
this pre-push local validation record.
