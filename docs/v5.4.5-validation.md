## Actual b10878 inference (Windows Vulkan)

On Radeon RX 9070 XT + Radeon AI PRO R9700, using the selected binary's device
ordering and AutoTuner-generated commands:

| Model/test | Result |
|---|---|
| Spark-X2.5-4B | “Runtime works”; structured `report_cache(cache="q8_0")` call after **2,630** prompt tokens; actual Q8 K/V log allocations |
| MiniCPM5-2B-F16 | “Runtime works”; same structured tool call after **2,574** prompt tokens; actual Q8 K/V log allocations |
| Qwen3.8-27B Q8_K_XL + DFlash2 Q4_K_M | **32,768** context, two-GPU split `0.333,0.667`, explicit draft on `Vulkan1`; returns “Draft device works” |
| Qwen3.8-Flash-Next IQ1_S, three shards | **4,096** context, explicit lazy **on**, loader confirms lazy PLE table; returns “Lazy loading works” |

For the Flash-Next table, GGUF offsets and Windows mapping/working-set APIs
measured only the **26.8222-GiB table range**: **266,240 bytes resident** at
readiness in that run. Whole-process RSS was **34.504 GiB** then **33.949 GiB**
after the request. Two preliminary checks failed because they compared table
size against whole-process/all-model-mapping residency; these were measurement
errors, not an eager-table finding. The corrected range-specific check passed.
This is neither a long-context stress test nor a hard active-page memory cap.

No b10878 HIP/CUDA/Metal inference, iGPU inference, video caching test, or complete
llama.cpp compiler rebuild is claimed. Linux/macOS CI validates AutoTuner source
and packaged startup, not inference on those GPU backends. No installed user
llama.cpp checkout or runtime was changed.

## Publication gates

Local build and checks precede the main push. The annotated **v5.4.5** tag must
only follow a successful main CI run: Ruff, Python **3.10–3.14** on Windows,
Ubuntu and macOS, plus Fedora, Arch, Mint, CachyOS, Kali and Debian source tests.

The tag workflow builds native Windows x64, Linux x64 and macOS arm64 ZIPs,
smoke-tests their frozen executables, and launches the same generic Linux ZIP
on Ubuntu, Fedora, Arch, Mint, CachyOS, Kali and Debian before publishing.
After publication verify all three public assets, architecture headers, POSIX
executable bits and GitHub SHA-256 digests. macOS remains a community build
without Apple notarization; use Finder right-click → Open / Privacy & Security
→ Open Anyway if Gatekeeper blocks first launch.
