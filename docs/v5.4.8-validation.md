## Fixes verified by the new regression tests

| Area | Defect | Verification |
|---|---|---|
| `hardware.detect_system` | Two cards from one detector with substring names (RTX 3060 / 3060 Ti, RX 9070 / 9070 XT) merged into one entry with the larger VRAM | Same-detector pairs stay separate; cross-detector duplicates still merge; differing PCI ids veto the name match; concurrent probes are serialized |
| `tuner.compute_config` | `max_fit_ctx == 0` (budget exhausted) was treated as "unknown": 32,768 auto context or an unclamped user pin | 14.9 GB dense model, 15.2 GB free, forced full offload: auto and a 131,072 pin both clamp to **2,048** with the clamp warning |
| Extra CLI flags | A repeated `--override-tensor`/`--lora`/… lost its second flag and leaked the value as a positional argument; pruning left the value behind | Both values emitted in order; identical repeats deduplicated; pruning removes flag and value |
| `ServerProcess` | Locale decoding of llama-server output (cp1252) ended the reader on a UTF-8 continuation byte, letting a full pipe block the server | UTF-8 with replacement; graceful stop resets the wrapper |
| OCR cancel | `response.close()` on the GUI thread waited for the whole in-flight page (up to the request timeout) | Socket abort (`shutdown` for Linux/macOS, handle close for Windows) wakes a blocked reader in < 3 s on Windows, Ubuntu and macOS CI; the existing fake-connection cancel test still passes; Office conversion cancel terminates `soffice` |
| GUI shutdown | Quit ended the process before the 10 s kill escalation of a still-running llama-server (its CTRL_BREAK never reaches a separate Windows console) | A child that ignores the signal is killed and awaited before exit |
| Control API | Windows `SO_REUSEADDR` let a second AutoTuner bind the active loopback port; backend resets were not mapped to 502 | Second bind raises `OSError`; the control-API suite passes |
| Profiles / packs / themes | One malformed YAML aborted loading of all profiles; scalar `patterns:` matched character-wise; a missing English pack killed the GUI; themes could not be saved without hard-link support | Malformed and non-mapping files are skipped with a warning; scalar lists coerced; English falls back to source text; exclusive create replaces `os.link` |
| Scanner / GUI | Tokenizer string arrays were read and decoded although skipped; the DXGI PowerShell fallback ran every 6 s; the CLI log viewer forced scroll-to-bottom and HTML-parsed `<think>` lines | Seeks past a 1,000-entry vocab and still reads the following keys; DXGI/WMI-free fallbacks only run for cards WMI did not cover; plain-text batched inserts with a 20,000-block cap |

The benchmark suite no longer writes a confirmation problem into the shared
`error` field (which invalidated the baseline and zeroed every score); it is
recorded as `confirmation_error` and only withholds the "confirmed" status.

## Actual inference on both backends

Hardware: Radeon RX 9070 XT + Radeon AI PRO R9700. Commands were built by
AutoTuner and are **token-identical to the v5.4.7 b10930 commands** apart
from the binary path; no blanket throughput claim is made.

| Model / case | Vulkan b10948 | HIP b10948 |
|---|---|---|
| Spark-X2.5-4B, Q8 K/V, 16,384 context | Exact “Runtime works”; structured `report_cache(cache="q8_0")` after 2,630 prompt tokens | Same checks pass |
| MiniCPM5-2B-F16, Q8 K/V, 16,384 context | Exact “Runtime works”; same tool call after 2,574 prompt tokens | Same checks pass |
| Qwen3.8-27B Q8_K_XL + DFlash2 Q4_K_M, 32,768 context | Two-GPU split, draft on Vulkan1; exact “Draft device works”, 7 draft tokens | Same checks pass (draft on ROCm1) |
| Qwen3.8-27B + matching BF16 mmproj, **no Draft** | Red image recognized and integers 1–40 returned | Same semantic result |
| Same image with **DFlash2 enabled**, gate bypassed | **Upstream HTTP 500 reproduced** (`X = 3`, `Y = 18`) | **Same failure reproduced** |
| Qwen3.8-Flash-Next IQ1_S, three shards, 4,096 context | Lazy PLE log and exact “Lazy loading works” | Same checks pass |

The image + DFlash2 row is **not a passing test**; it is the evidence that the
b10896+ gate must stay. v5.4.8 blocks this combination before launch for every
build from b10896 on and names both working alternatives.

Lazy loading: the 26.8222-GiB PLE table (exact **28,800,138,240-byte** range)
had **266,240 resident bytes** at readiness on both backends, identical to
b10930. Whole-process RSS at readiness was 28.02 GiB (Vulkan) / 22.66 GiB
(HIP) in this run versus 15.30 / 15.04 GiB on b10930 with the identical
command; the lazily read table itself stayed at the same 266,240 bytes, so
the difference lies in the file-backed pages of the other two shards (page
cache state), not in AutoTuner's plan. These are point-in-time observations,
not residency limits.

## Publication gates and limits

The local build precedes push. The annotated **v5.4.8** tag is created only
following successful main CI: Ruff, Python **3.10–3.14** on Windows, Ubuntu
and macOS, plus Fedora, Arch, Mint, CachyOS, Kali and Debian source tests.
The tag workflow builds native Windows x64, Linux x64 and macOS arm64 ZIPs,
smoke-tests them and launches the same generic Linux ZIP on seven distributions
before publication. Published ZIPs are then checked for architecture, executable
bits and GitHub SHA-256 digests. CI's Windows EXE is independently built with
Python 3.12 and need not match the local EXE hash.

The best-effort CTRL_BREAK delivery into llama-server's own console
(`_send_ctrl_break_to_new_console`) could not be exercised in this session's
console-less automation; the kill escalation and the new wait-before-exit are
what the regression test verifies. Two review findings were left open on
purpose: the control API still clears its active-model state before the GUI
rejects a switch (restoring it blindly could name a server the GUI already
stopped), and the benchmark's 2-hour total deadline still discards completed
measurements. No CUDA/Metal/iGPU inference, new-model weight inference, or
universal long-context/performance guarantee is claimed. The qwen4exp
indexer-V reserve and the MTP draft-context plan intentionally stay
conservative on b10948. Linux/macOS packaging CI is not GPU-inference
validation. macOS is a community build without Apple notarization: Finder
right-click → Open / Privacy & Security → Open Anyway may be required.
