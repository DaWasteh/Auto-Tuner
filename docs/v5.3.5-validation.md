# AutoTuner v5.3.5 validation

Validation date: 2026-08-31

## Scope

This release makes the Qt hardware strip responsive, removes the aggregate
Quick-performance timeout, adds a dedicated IBM Granite 4.2 profile, and updates
the verified llama.cpp compatibility ceiling to b10717. Validation covers Qt
minimum-size and theme/splitter regressions, unlimited-run deadline semantics,
profile precedence and stripped-metadata fallbacks, official GGUF integrity and
metadata, real Vulkan/HIP inference, structured reasoning/tool output, the full
source suite, and a fresh Windows frozen build.

## Responsive hardware strip

The former fixed-height `QHBoxLayout` treated every hardware label's complete
single-line text as a minimum width. In the original offscreen reproduction,
long but valid CPU/GPU descriptions increased the window minimum from 1,390 to
2,630 pixels.

`_ResponsiveSystemBar` now gives labels horizontally ignored, word-wrapped
height-for-width sizing and reflows four fields as:

- four columns when their natural text width fits;
- two columns at ordinary constrained widths; and
- one column below 640 pixels.

Its explicit current-width height hint prevents Qt from calculating hundreds of
bogus vertical pixels at an almost-zero ignored-label width. An initial one-line
minimum also prevents the first theme refresh from taking space from saved
splitter proportions. The offscreen regression keeps the main-window minimum at
its pre-hardware baseline, observes the expected 2x2 positions and multi-line
height, then expands to four columns at a wide size. The existing theme test
confirms both nested splitters retain their exact sizes.

## Unlimited Quick-performance runs

Quick keeps its bounded workload (at most 3.125% context, a 16,384-token prompt
cap, 128 decode tokens, seven search candidates, and one confirmation), but sets
`total_timeout_s=0`. `BenchmarkRunner` now defines non-positive aggregate time as
unlimited while retaining:

- the 300-second server-startup bound;
- the 900-second per-request bound;
- bounded candidate/search counts; and
- immediate user cancellation.

The old suite-level `model_time_budget_s` deadline and `_deadline_cap` handoff
were removed, so an earlier slow mode cannot skip the remaining modes for that
model. Regression tests prove that deadline checks remain safe at zero, startup
still waits within its own timeout, and even stale job metadata containing a
nanosecond shared model budget cannot suppress either suite job.

## IBM Granite 4.2 profile

`settings/granite-4_2.yaml` matches the explicit dotted, hyphenated, and
underscore Granite 4.2 filename forms without claiming the shared `granite`
architecture fallback. This preserves Granite 4.1 routing for named older
requants and leaves opaque `granite` files on the conservative generic profile.
The profile provides:

- 131,072 native context tokens;
- temperature 1.0 and top-p 0.95 in both chat and coding modes;
- top-k/min-p/presence-penalty disabled and repeat penalty 1.0;
- explicit `--jinja`; and
- generic `ngram-mod`, not `draft-mtp`.

The completed official GGUF was checked directly:

Scanner tests cover both authoritative template detection and every accepted
filename spelling when a community quant strips tokenizer metadata. Profile

IBM advertises a separate 512K long-context extension only for the 30B model,
but all three checkpoint configs and the official serving examples use 131,072.
No unverified generic YaRN recipe is enabled by this release.

## Remaining bounds

- The 8B Q8_0 checkpoint was the completed Granite 4.2 file available for the
  release gate. The still-downloading 8B BF16 and 30B Q4_K_M/Q6_K variants share
  the same verified `granite` loader/template contract but were not used as
  redundant runtime gates.
- Granite 30B's advertised 512K extension remains opt-in/manual until a precise
  GGUF scaling recipe is validated; automatic context stays at native 128K.
- Quick suites intentionally have no aggregate wall-clock cutoff and can run for
  hours across many slow models. Startup/request failures and user cancellation
  remain the bounded escape paths.
