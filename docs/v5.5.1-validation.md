# AutoTuner v5.5.1 validation

Local checks: **2026-09-18**, Windows x64, Python **3.14.5**. Runtime under
test: the **b11030** HIP and Vulkan trees built that morning by the unchanged
Windows recipes (and re-verified by all four recipes, including the
**v0.4.1** / b10964 stable pair) from the [b11030 audit](llama-b11030-audit.md);
the same binaries are hashed in [llama-b11030-server-flags.json](llama-b11030-server-flags.json).

This release re-audits llama.cpp b10977→b11030, adds the `dfm-mimir.yaml`
profile for DFM Mimir 1B (`hrm_text`), adds the Nemotron latent-MoE MTP
loader gate (PR #29018, b11025+) and moves the DeepSeek-V4.1 and
vision+DFlash2 gate wording to b11030. The planner's placement, KV and
speculative logic did not change; the only new pre-launch refusal is the
metadata-driven Nemotron gate.

## Observed, not changed

- Nemotron 3 Nano Omni decodes an order of magnitude slower on Vulkan than
  on HIP on this workstation (5.8 vs 57.9 t/s on the short deterministic
  answer, 5 vs 3 graph splits with the two-GPU layer split); both backends
  answer correctly and there is no b10977 Nemotron baseline, so this is
  recorded, not acted on. Prefer the HIP runtime for Mamba-2 hybrids here.
- Nemotron 3 Super's MTP block is gated on upstream's own reproduction (PR
  #29018); no Super GGUF is on this workstation, so the gate has unit
  coverage but no local run. Lightning/Nano MTP behaviour is unchanged.
- DFM Mimir has no local GGUF either; the profile is covered by unit tests
  (matching, gate, context, command, KV arithmetic, pack notes).
- Maple on HIP still keeps the TQ2_0 expert tensors on the CPU (no CUDA/HIP
  ternary kernels); the profile note is unchanged.
- The follow-ups recorded in [v5.4.9](v5.4.9-validation.md) (switch stops the
  old server before planning; CTRL_BREAK delivery unverified in automation)
  are unchanged.

The publication gates (main CI on Python 3.10–3.14 across Windows, Ubuntu,
macOS and six Linux distributions, the tag workflow's native ZIP builds and
smoke tests, digest/architecture verification of the published assets) are
the same as in [v5.5.0](v5.5.0-validation.md).
