Local verification on 2026-10-09/10: Core Ultra 9 285K, AI PRO R9700 32 GB +
RX 9070 XT 16 GB, 47 GiB RAM, Windows 11, llama.cpp **b11538** (`79e2e74eb`)
HIP and Vulkan. See the [b11538 audit](llama-b11538-audit.md).

## Live chain (both backends)

Twenty planner/runtime scripts per release convention passed on HIP and
Vulkan: profile/mode command matrix, runtime, text DFlash2, vision-only,
image + DFlash2 (**152/168** accepted drafts on each backend, as on b11371),
Flash-Next lazy PLE, Gemma 4 + MTP assistant, Maple TQ2_0, Nemotron Nano Omni,
Ling 3.0 (tool calls with thinking, `auto` and `required`), FastContext and
Muse Glimmer tool calls and `json_schema`. Negative loads confirm the
stock-runtime blocks: four Agnes (ROCmFPX), four Bonsai 2 (Prism) and two
Xing loads fail as expected. The chain ran twice: once while the code was
still changing and once more on the final code (2026-10-10 00:08–00:28).

New in this release, on both backends:

- **Escha (issue #7):** stock b11538 refuses `Escha-Qwen3.8-27B-W2.gguf`
  alone and with its head (`check_tensor_dims: tensor 'blk.0.ssm_out.weight'
  not found`); AutoTuner's model check refuses it first and names the fork.
  The scan pairs the original head file with the target; the head is a
  standalone drafter, not a model.
- **K2 Horizon:** 1B (dense, in-GGUF YaRN to 131,072) and MoVA-36B-A4B Q8_0:
  thinking answer with separated reasoning, `get_weather` tool call with
  `auto` and `required`.
- **Decision models:** d1-3B and d1-omni-600M with mmproj answer
  choice/noul/score questions, a >1,024-token state and red/green/blue image
  questions (all correct); Julia-1, Laya and Kev-4B unchanged. Clef-Flash:
  text questions pass with and without mmproj; images fail with HTTP 500 on
  the 2026-10-02 conversion (template without image slot) and pass with the
  2026-10-05 conversion (red and blue decided correctly).
- **EmbeddingGemma 2 (new profile):** ctx = batch = ubatch = 8,192 instead of
  a 262,144-token chat plan; 768-dim vectors, matching document 0.87 vs
  unrelated 0.62, a 6,828-token document in one request.
- **Qwen3.8 Flash Next + separate MTP head:** `GGML_ASSERT(buffer)` with
  `draft-mtp` on both backends (gate kept, verified build now b11538); the
  same plan without speculation answers four requests normally.

The first live run overlapped with a game on the RX 9070 XT
(`PioneerGame.exe`, about 75 % GPU), so its throughput figures are not
comparable with v5.6.1; functional results are unaffected. The final run
was quieter: its short-request figures are at or above b11371 (for example
Vulkan vision-only 19.8 vs 19.5 tok/s, HIP Nemotron Nano Omni 71.6 vs 67.8,
Gemma 4 + MTP assistant 59.6 / 51.4), and K2-Horizon-MoVA-36B-A4B decodes
65 tok/s on Vulkan and 45 tok/s on HIP (12–13 tok/s while the game ran).
One check differs: Ling-3.0-flash AD-IQ3_M on **HIP b11538** ends the
"integers 1 through 80" bench answer after "11," (temperature 0, end token at
48 % probability), so `ling3_test.py` reports `bench_ok = False` while its
tool, thinking and text checks pass. A five-prompt probe shows this is HIP
numerics with this 3-bit quant rather than a b11538 regression: HIP b11371
completes that list but loops ("Waste, Waste, …") on a 1-to-50 list, HIP
b11538 writes "三十八" for 38 there, and Vulkan b11538 answers all five
prompts correctly. `GGML_CUDA_FORCE_CUBLAS=1` changes nothing, so the MMQ
fixes are not the cause. No AutoTuner change; noted for a later upstream
look.

## Throughput

R9700 only, mirrored run order, three internal repeats (the RX 9070 XT ran a
game): stock **b11538 matches the opt-in `rdna4moe_b11371` build** for Vulkan
MoE prompt processing (+15.2…+42.7 % against stock b11371; upstream revert
#29936 in b11423), dense Vulkan and generation within −1.8…+3.1 %, HIP prompt
processing +3.6…+7.2 % and generation −1.1…−3.0 %. Full table in the audit.

`--moe-cache-mib` A/B (R9700, mirrored, two runs per variant): Vulkan decodes
38…62 % slower in a partial hybrid plan and cannot allocate 8 GiB; HIP gains
+3…16 % decode for −13…32 % prompt speed (an 8 GiB cache aborted with a ROCm
launch failure). Auto keeps the cache off; tables in the audit.
