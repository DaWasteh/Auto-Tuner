actual b11105 binaries, and run **sequentially**, Vulkan then HIP. The
previous Qwen3.8 UD-Q8_K_XL target is no longer installed; the current
**Qwen3.8-27B-Q8_0** replaces it. These are correctness checks, not controlled
speed comparisons with the older quant. Every script checks for an existing
llama-server before starting and terminates only its own process.

## New model, environment and negative-load checks

`new_models_test.py` runs both FastContext 4B Q8_0 variants and Muse Glimmer
30B UD-Q5_K_XL on **each backend**, through the real scanner/profile/planner
and command preparation. Every process inherits
`LLAMA_ARG_PRESENCE_PENALTY=1.7`, while the generated CLI specifies zero.
`GET /props` confirms **presence_penalty 0.0** and the exact profile's
sampling values. All six model/backend combinations return the correct
`report_cache({"cache":"q8_0"})` call for both `tool_choice: auto` and
`required`, with no preparation warnings.

Muse's log selects **Muse Glimmer / peg-native**. The local quant still
emitted reasoning before its tool call despite the no-reasoning request;
reasoning and `tool_calls` were separated correctly. Thus these are actual
tool/parser integration checks, **not** an isolated local reproduction of
the first-token-only edge fixed by #29242. That edge is verified from the
upstream parser diff and its added `test-chat` regression.

The final command matrix parses **174 profile/mode commands per backend**
on the real server (91 bundled profiles, excluding diffusion and blocked
profiles); the K2 stock-runtime gate also rejects as expected.

| Raw load with AutoTuner gate bypassed | Vulkan / HIP b11105 | AutoTuner verdict |
|---|---|---|
| Agnes ROCmFP4 STRIX_LEAN | exit 1, unknown type 101 | Refused by tensor-type gate |
| Agnes ROCmFP4 COHERENT | exit 1, unknown type 100 | Refused by tensor-type gate |
| Bonsai 2 PQ2_0 / PTQ1_0 | exit 1, unknown types 142 / 143 | Refused by `prism.hadamard` metadata gate |
| Xing4.0 IQ4_NL | exit 1, `unknown model architecture: 'xing4_0'` | Refused by profile and architecture guard |

A first iteration of the inherited Bonsai audit helper checked only the
profile-level minimum, not the metadata-level fork gate, and its assertion
failed. The helper was corrected to call `check_model_build` on each actual
GGUF, then the complete final matrix/negative-load sequence passed. No
product gate change was needed for Bonsai.

## Source regressions and scope

`test_llama_b11105.py` covers the unchanged option set and changed help
hashes, explicit zero presence penalty, MiMo b11102 gate/matching/sampling,
trunk-only MTP refusal and asymmetric interleaved KV arithmetic, both
FastContext variants, Xing filename/renamed-architecture protection,
VoxCPM2 filename/metadata protection without a generic minicpm4 veto,
Muse parser notes in all nine packs, the b11105 vision/DFlash2 block and
the isolated Voice Lab recipe. Historical tests now check the updated
V4.1/gate wording without changing their pinned old manifests.

- Full pytest: **826 passed, 9 skipped** in both final runs (97.67 / 97.79 s).
- Ruff **0.16.0** check: clean; format check of all changed Python files:
  clean. Compileall: clean.
- PowerShell parser accepts the Voice Lab PS1. Its two target executables
  exist in the isolated Voice Lab build; this release does not rebuild them
  or claim a new TTS quality test.
- `models_metadata.md` is included byte-for-byte as supplied, SHA-256
  `9f57c4021c810741e67bab3b5664bd44415d3e7c045496483ed28f9ac8eb096b`.
- **Not locally inferred:** MiMo-V2.6 (no weights), HunyuanOCR/DFlash (no
  weights), Metal/SYCL/OpenCL/WebGPU/Hexagon runtime paths. MiMo has
  source/command/unit coverage, not a local inference/speed claim.
- Existing specialized forks and their recipe pins/patches are unchanged.
  A stale-closed issue or a candidate patch is not treated as proof that a
  workaround can be removed; see the audit's issue table.
