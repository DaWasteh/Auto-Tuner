# Public benchmark dashboard (GitHub Pages)

The public AutoTuner benchmark dashboard is deployed at:

**<https://dawasteh.github.io/Auto-Tuner/>**

The site is a dependency-free snapshot of the benchmark evidence stored on the
maintainer's machine. GitHub cannot read `~/.autotuner`, so refreshing the page
has two explicit stages: export the local evidence, then push the generated
static file.

## Refresh the published results

From the repository root, run:

```bash
python publish_benchmarks.py
```

This command:

1. reads all Quick pass, Standard, and Custom evidence from
   `~/.autotuner/autotuner_settings.json`;
2. writes `benchmark-site/index.html` atomically;
3. removes model and runtime directory paths while retaining model filenames,
   hardware, timings, settings, failures, and candidate data; and
4. refuses to finish if the public HTML still contains a local absolute path or
   a script.

To export another portable/test data directory:

```bash
python publish_benchmarks.py --data-dir /path/to/.autotuner
```

Review `benchmark-site/index.html`, commit it, and push `main`. The
[Deploy benchmark page workflow](../.github/workflows/pages.yml) validates the
committed page, uploads only `benchmark-site/`, and deploys it to the protected
`github-pages` environment. A successful deployment updates the URL above.

The local reports generated by the GUI under `~/.autotuner/reports` remain local
and may show full paths. Only the explicit public export is committed.

## Required GitHub repository settings

For this repository, Pages uses a **GitHub Actions** publishing source. On a new
fork or repository, check these once:

1. Open **Settings → Pages**.
2. Under **Build and deployment → Source**, select **GitHub Actions**.
3. Ensure GitHub Actions are enabled under **Settings → Actions → General**.

No Pages branch, `gh-pages` branch, personal access token, repository secret,
custom domain, or Jekyll configuration is required. The workflow's validation
job receives only `contents: read`; a separate deployment-only job never checks
out repository code and alone receives `pages: write` plus `id-token: write`.

GitHub Pages is available for this public repository. Remember that the rendered
model names, hardware specification, timings, and benchmark errors are public;
inspect the generated page before committing if a future record contains data
you do not want to publish.

## Troubleshooting

- **The page still shows old results:** confirm that `benchmark-site/index.html`
  changed, was pushed to `main`, and the **Deploy benchmark page** workflow
  completed successfully.
- **Pages reports that no site exists:** select **GitHub Actions** under
  **Settings → Pages**, then rerun the workflow.
- **The exporter reports a local path:** inspect the named benchmark/error data
  and extend the redaction at the report boundary rather than bypassing the
  validation.
- **A fork has no Pages URL:** public forks can enable Pages independently; the
  URL uses the fork owner's account and repository name.
