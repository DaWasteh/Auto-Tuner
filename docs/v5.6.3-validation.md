## Measurements

- **`--spec-draft-n-ubatch`** (AutoTuner plans, mirrored 0/64/16/16/64/0):
  Vulkan Qwen3.8-27B Q8_0 + DFlash2 −1,289 MiB GPU memory with 64, Gemma 4
  31B + MTP head −224 MiB on both backends; prefill, decode and accepted
  drafts unchanged. Table in the audit.
- **DFlash2 plan, b11538 vs b11669** (mirrored, with and without the
  draft): identical within run variation on both backends. Vulkan decodes
  19.7 tok/s without and 35.8 tok/s with DFlash2 (+82 %).
- **llama-bench** on the R9700 (mirrored, `-r 3`): b11669 within ±2 % of
  b11538 on both backends (Vulkan MoE prompt +1…2 %). Table in the audit.
- **Open finding — HIP two-GPU split of a hybrid model:** the plan AutoTuner
  makes for Qwen3.8-27B Q8_0 when a DFlash2 draft is budgeted splits the
  layers over both cards (`HIP_VISIBLE_DEVICES=1,0`, 0.333 / 0.667, every
  buffer within its card per `-lv 4`). Without the draft that split decodes
  **4.4 tok/s on HIP** but 19.7 tok/s on Vulkan; the same model on the R9700
  alone decodes 19.7 tok/s on HIP and 20.6 tok/s on Vulkan (dedicated GPU
  memory 27.9 GB, nothing spilled). With DFlash2 the HIP split reaches
  10.5 tok/s against 35.8 on Vulkan. b11538 behaves identically, so this is
  not a b11669 regression. Alone, both cards decode a MoE model equally fast
  under HIP (119 / 120 tok/s); the RX 9070 XT prefills much slower there
  (820 vs 2,790 tok/s). Not changed in this release; candidate for a
  planner rule (prefer one GPU on HIP for recurrent hybrids) after more
  measurements. Vulkan is the better backend for such split plans today.
