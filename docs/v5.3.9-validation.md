# AutoTuner v5.3.9 validation

Validation date: 2026-09-04

## Scope

This release validates AutoTuner against exact stock llama.cpp b10786, adds
the Nemotron 3 Super and Nemotron Labs 3 Puzzle profiles with the b10786
per-layer expert gate, extends the external control API for benchmark
campaigns (runtime selection, launch snapshot, discovery file), localizes every
profile explanation in all eight bundled language packs, improves the
performance search, redesigns the HTML benchmark report, and rebuilds the
tracked Windows application.

The upstream review is recorded in
[`llama-b10786-audit.md`](llama-b10786-audit.md).

## External control API

New and extended endpoints are documented in
[`control-api.md`](control-api.md):

- `GET /api/v1/runtimes` lists every toolbar llama build with backend, probed
  build identity, default flag, and availability;
- `POST /api/v1/switch` accepts `runtime_id` and `timeout_s`, returns
  409 `runtime_unavailable` for unknown or unusable builds, and treats a
  different runtime as a real transition while staying idempotent otherwise;
- `GET /api/v1/status` returns `ready`, `backend_url`, `alias`,
  `backend_api_key`, `active_runtime`, `pid`, `log_path`, `runtime`, `model`,
  `launch`, `devices`, `env`, and a redacted `command_line`;
- `GET /api/v1/models` adds `size_bytes`, `quant`, `params_b`, `family`,
  `architecture`, and `default_runtime_id`;
- `~/.autotuner/control_api.json` is written atomically (POSIX mode 0600)
  whenever the gateway starts, stops, or its token changes; the token is
  present only while enabled.

The Pi extension reads the discovery file first and falls back to a bounded
regex scan of the legacy settings file, which fixes the previous 2 MiB size
guard that silently disabled discovery on large settings files. The Pi
runtime test now also exercises the sidecar path against a 3 MiB settings
file.

The contract was agreed with the Pi extension and Supercalc benchmark
sessions before release; both clients were implemented against
`docs/control-api.md`.

## Performance search and report

`model_benchmark.py`:

- thread stage adds a decoupled `threads=physical / batch_threads=logical`
  probe and, for fully offloaded models, a small-thread probe;
- batch stage keeps the validated classic family first and appends a
  geometric neighbourhood of the seed plus 2048/2048 and 4096-token probes;
- a refinement stage hill-climbs beyond the measured family while budget
  remains and stops on the first step that fails the 3% noise threshold;
- thread finalists are distinct generation-thread counts; the runner-up still
  receives the classic family;
- the Standard budget rises from 14 to 18 candidates.

`performance_report.py` adds the *Recommended settings per model* section, a
metric legend, an applied-settings column in the winner table, ranked candidate
charts (12 fastest per run) with settings captions, and collapsed per-run
diagrams. Public-export redaction was re-verified for the new text.

## Remaining bounds

- Live campaign runs through the control API depend on the user enabling the
  gateway in the GUI; the Supercalc session performs them after release.
- `log_path` in `/api/v1/status` is only available on Linux/macOS, where
  llama-server output is captured to a file; Windows launches use a console.
- Translations for Dutch, Swedish, Japanese, French, Greek, and Polish were
  produced from the English source and reviewed for technical fidelity, not by
  native reviewers.
- The benchmark refinement stage only runs when the candidate budget exceeds
  what the thread and batch stages consume; Quick keeps its 7-candidate cap.
