## Real external draft / device-order regression

Target: `Qwen3.8-27B-UD-Q8_K_XL`; drafter:
`Qwen3.8-27B-DFlash2-Q4_K_M`; context **32,768**, draft depth **7**.
Target weights use both the RX 9070 XT (16 GB) and R9700 (32 GB).

| Backend | Final visible order | Target split | Main / draft device | Result |
|---|---|---|---|---|
| Vulkan | physical `0,1` | `.333,.667` | `1` / `Vulkan1` | generation passed |
| HIP | physical `1,0` | `.333,.667` | `1` / `ROCm1` | generation passed |

Logs show target model buffers on both GPUs, but the **1,079.61-MiB draft
model buffer only on the selected R9700**, plus active DFlash speculation
and accepted draft tokens. Both generated `Draft device works`.

The initial HIP pin-only test exposed the shared-head scheduler abort:
`pre-allocated tensor (output.weight) in a buffer (ROCm1) that cannot run
the operation (NONE)`. The correction places the primary last in the
visible layer-split order, keeping target output and draft on the same GPU.
The same HIP test then passed. Regression tests cover both enumeration
orders, Vulkan/CUDA/ROCm selectors, aliases, unresolved identity and rejection
of an incompatible shared-output placement. Actual CUDA/SYCL/Metal hardware
inference was not performed.

## Real Qwen Flash Next lazy-table test

Target: three-part `Qwen3.8-Flash-Next-UD-IQ1_S`, Vulkan b10863, **4,096
context**, no vision or speculative drafter. The log confirms:

```text
per_layer_token_embd.weight (size = 27465 MiB) lazy read enabled
```

The 51.2B-entry table occupies **26.8222 GiB**. Entire process RSS was
**21.657 GiB** at readiness / **22.568 GiB** after generating
`Lazy loading works`. Thus the whole table was not resident in that run.
These are process-wide numbers, not table-only measurements. Active rows and
OS cache still occupy RAM; the planner's 5% working-set reserve is a heuristic,
not an enforceable cache cap or a long-workload residency guarantee.

## K2 Horizon and remaining boundaries

K2's real download header was inspected, and the official config, IFM graph
and compatible template were source-checked. Its new profile fails closed on
stock b10863 and uses whole-layer placement rather than the unsafe generic
FFN-only MoE estimate. **K2 requires the IFM fork; its inference/tool parser
has not been hardware-tested here.** No fork was automatically installed,
no giant Kimi-K3 model was loaded, and no full benchmark campaign or maximum-
context quality sweep was represented as completed.

Existing benchmark records/public dashboard data remain unchanged. Search
schema 5 invalidates automatic reuse of pre-fix winners without deleting
historical measurements or user-authored profiles.
