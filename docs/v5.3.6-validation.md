# AutoTuner v5.3.6 validation

Validation date: 2026-09-01

## Scope

This release repairs the Fedora hardware-strip regression test, aligns generated
commands with llama.cpp's current lazy-read option, hardens value-bearing option
merges, raises the qwen4exp correctness gate, and quarantines the upstream
b10741-b10748 NextN regression. Validation covers exact b10743 source/help,
real Vulkan model loading and decoding, Vulkan/HIP draft preflights, all shipped
profile options, Qt font-metric-relative behavior, the full source suite, and the
three-platform release gate.

The detailed upstream review is
[`llama-b10743-audit.md`](llama-b10743-audit.md).

## Fedora hardware-strip regression

GitHub Actions run `33397942834` failed only on Fedora 44:

```text
1 failed, 445 passed, 5 skipped
test_hardware_bar_wraps_without_widening_main_window
assert window._sysbar.column_count == 2
assert 4 == 2
```

Fedora installed PyQt6 6.11.0 / Qt 6.11.2. Its font metrics allowed the four
hardware labels to fit at the default 1,320-pixel window width, while the older
test assumed that this width must produce two columns. The product widget was
already behaving correctly.

The test now keeps the actual product contracts:

- long labels must not widen the main window;
- the compact width is derived from `_single_row_width() - 1` and must produce
  the 2x2 grid;
- a width above the same measured threshold must produce four columns; and
- height bounds are relative to `heightForWidth()` and the current font.

The focused offscreen test passes locally. Fedora itself is revalidated by the
branch CI distro job before tagging because Docker Desktop was not available for
a local Fedora container rerun.

Source option extraction found no option-name additions or removals from

## NextN/MTP regression boundary

b10741 `9d817213a` (PR #28159) made the generic loader aware of NextN before
`n_layer()` calls, but b10741-b10748 contain two incomplete cases. Per-layer
FF/head metadata arrays can be checked against the wrong reduced count, and a
standalone all-NextN assistant contradicts the new global strict-less-than
assertion. b10749 is the first tag containing both fixes:

```text
d11b3cc7e  model: load relevant arrays with n_layer_all (#28173)
73159c303  model: fix gemma4-assistant (#28183)
```

The exact real Gemma draft head reproduces the b10743 failure:

```text
Model: I:\models\Google\Gemma 4 v2\mtp-gemma-4-12b-it-v2.gguf
Architecture: gemma4-assistant
Failure: GGML_ASSERT(hparams.n_layer_nextn < hparams.n_layer_all) failed
```

The new Vulkan and HIP preflights reject that draft before process launch and
name b10749+ or b10740 and earlier as valid ranges.

For embedded MTP, b10741-b10748 command preparation removes only `draft-mtp`,
its optional external MTP head, and `--spec-draft-*` parameters. A surviving
`ngram-map-k4v` method and all core target arguments remain. Array-backed target
metadata that cannot reach even the base graph is rejected before launch by the
GUI, terminal, and benchmark paths.

## Real Qwen3.6 embedded-MTP fallback

The real `Qwen3.6-27B-MTP-IQ4_XS.gguf` reports qwen35 block count 65 and one
NextN layer. An unadapted exact-b10743 `draft-mtp` launch loaded the target but
failed while creating the MTP context. The prepared command recorded:

```text
draft-mtp disabled for llama.cpp b10743
(upstream NextN regression in b10741-b10748; fixed in b10749+)
```

The target then loaded fully on the R9700, became healthy in 13.74 seconds, and
completed a 15-token prompt plus 8-token decode at 10.63 decode tokens/s. The
loader's unused `blk.64.nextn.*` warnings are expected for this deliberate base
fallback. No core model-loading, placement, context, sampling, or performance
flag was removed.

including the Fedora distro job. The tag workflow must then build and smoke-test

- Windows x64 ZIP;

The GitHub release and all three assets are verified after workflow completion.
Generated local `*.help.txt` files are excluded from the release tree.

## Remaining bounds

- b10743 is supported for non-MTP operation and for scalar-metadata embedded
  NextN targets through the explicit base-model fallback. Users who require MTP
  on these models must use b10749+ or b10740 and earlier.
- A wrapper whose numeric build cannot be probed retains the existing
  warning-compatible policy; AutoTuner does not guess that an opaque fork is in
  the broken build range.
- The qwen4exp runtime used Vulkan because that exact split GGUF and dual-GPU
  placement were available locally. HIP's exact b10743 CLI surface was checked,
  while source parity is guaranteed by both binaries reporting commit
  `8887a48f0`.
