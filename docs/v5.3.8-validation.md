# AutoTuner v5.3.8 validation

Validation date: 2026-09-02

## Scope

This release validates AutoTuner against exact stock llama.cpp b10760, adds
focused profiles for popular supported model families, applies b10749
correctness gates to recurrent SSM models, removes one unused Windows HIP CMake
argument without hiding upstream warnings, and rebuilds the tracked Windows
application.

Validation covers the full b10743-to-b10760 upstream range, server-help and
profile-flag compatibility, all 74 YAML profiles, a clean 630-target HIP build,
real deterministic generation across both local AMD GPUs on HIP and Vulkan,
the complete source suite, and the newly frozen Windows executable.

The detailed upstream and warning analysis is recorded in
[`llama-b10760-audit.md`](llama-b10760-audit.md).

## Model profiles and correctness gates

The profile bundle increases from 67 to 74 files. Added profiles:

- `gemma-3.yaml`;
- `gemma-3n.yaml`;
- `mistral-small-3.yaml`;
- `llama-4.yaml`;
- `kimi-linear.yaml`;
- `paddleocr-vl.yaml`; and
- `ornith-1_5.yaml`.

`llama-3-4.yaml` is replaced by the narrower `llama-3.yaml`; Llama 4 now has
its own official sampling and 10M/1M family context contract. Longest-pattern
selection keeps Ornith 1.5 ahead of the older Ornith family profile. Filename
and architecture tests ensure the new profiles do not steal Llama 3, Kimi K2,
Ling 2.6, Gemma 4, older Ornith, or generic Qwen models.

Ling 3, Kimi-K3, and Kimi Linear require b10749. That is the first tag
containing commit `f28493c78347`, which marks their recurrent `ssm_a` tensors
with the corrected no-scan contract. Tests preserve both the earlier loader
introduction versions in profile notes and the later executable safety gate.

Profile loading, family matching, context ceilings, sampling maps, b10760
minimums, architecture fallbacks, OCR prompts, multimodal caveats, and command
matrices are covered by the source suite. The source smoke reports:

```text
AutoTuner v5.3.8 frozen smoke test OK (74 profiles)
```

## Windows HIP build and warnings

The shared HIP recipe no longer passes `CMAKE_HIP_COMPILER`. llama.cpp's current
Windows HIP configuration consumes ROCm clang through `CMAKE_C_COMPILER` and
`CMAKE_CXX_COMPILER`; the extra variable only produced CMake's unused-variable
warning. Required choices remain intact, including Ninja, `gfx1201`,
`GGML_HIP=ON`, Flash Attention/all-quant FA, HIP graphs, and
`GGML_CUDA_NO_PEER_COPY=ON`.

The audit script preserved the known build, executed the authoritative
`llama_prerelease_hip_build.ps1` recipe, checked native process exit codes, and
retained the replacement only after all verification passed. It completed all
630 Ninja targets. The final cache contains:

```text
GGML_HIP:BOOL=ON
GGML_VULKAN:BOOL=OFF
GGML_CUDA_NO_PEER_COPY:BOOL=ON
GGML_HIP_GRAPHS:BOOL=ON
GGML_CUDA_FA_ALL_QUANTS:BOOL=ON
CMAKE_HIP_COMPILER: absent
```

The configure log contains neither a `CMAKE_HIP_COMPILER` cache entry nor
CMake's `Manually-specified variables were not used by the project` warning.
No backup directory remains after successful replacement.

Warnings were not disabled or promoted to errors. The clean log has 11,417
compiler warning records at 239 source locations; 11,395 records (99.807%) are
GGML HIP/CUDA kernels or repeated template instantiations. The remaining 22 are
upstream/vendored portability, optional-example, and ignored-`nodiscard`
diagnostics. There is no AutoTuner source warning and no recipe/configuration
failure hidden by this classification.

## Real backend semantics

Both exact b10760 backends loaded the same bounded 4B Qwen3 validation model
with full GPU offload, Flash Attention, a two-device tensor split, fixed seed,
temperature zero, top-k one, disabled thinking, and one local server slot.
Each `/v1/chat/completions` response had to equal its backend-specific oracle
exactly:

```text
HIP multi-GPU semantic output verified: HIP MULTI GPU OK
Vulkan multi-GPU semantic output verified: VULKAN MULTI GPU OK
```

This checks generated output rather than accepting device enumeration or
throughput as correctness evidence. Both test servers became healthy, answered
the request, and were terminated with their process trees.

## Remaining bounds

- Gemma 3n b10760 support is text/vision; audio tensors are still skipped and
  the profile does not claim audio inference.
- PaddleOCR-VL covers deterministic llama-server element recognition. The full
  external PaddleOCR layout/postprocessing pipeline remains outside AutoTuner.
- Kimi-K3 b10760 support is the text path; its converter intentionally skips
  the native vision projector.
- Warnings in stock llama.cpp HIP templates remain visible for upstream fixes.
  AutoTuner neither patches the audited upstream source nor suppresses them.
- GitHub Release publication is an external CI gate and is verified from the
  workflow run after the tag push.
