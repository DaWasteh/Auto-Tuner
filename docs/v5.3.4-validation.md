# AutoTuner v5.3.4 validation

Validation date: 2026-08-30

## Scope

This release changes the global HTML model overview, the Qt toolbar and runtime
localisation, per-user custom language packs, application settings persistence,
local llama-server lifecycle control, an authenticated OpenAI-compatible proxy,
dynamic Pi provider registration, frozen resources, and release-asset staging.
Validation covers report alignment, translation completeness/import safety,
queued Qt/HTTP transitions, concurrent proxy traffic, credential boundaries,
source and frozen startup, and the rebuilt local Windows application.

## Stacked and aligned model overview

Decode, prompt/encode, and end-to-end winner panels render as vertical sections.
Each uses the same intrinsic chart width and exact model/backend/build ordering.
One bottom horizontal scrollbar drives every panel; sticky section headings and
ARIA labels preserve orientation and accessibility. Regression checks reject a
return to independent scroll containers, side-by-side panel wrapping, or
inconsistent model ordering.

## Toolbar and localisation

The primary toolbar retains frequent model/runtime controls. Fonts, language,
Update, and Settings are owned by a secondary `QToolBar`; clicking the ellipsis
checks/unchecks that toolbar, while pointer Leave events do not close it.

English (UK) is the canonical source/fallback. All canonical strings are present
in the eight packaged schema-1 packs:

- English (UK)
- Deutsch
- Nederlands
- Svenska
- 日本語
- Français
- Ελληνικά
- Polski

The seven translated packs were reviewed as complete built-ins rather than
machine-generated partial overrides. Runtime state is stored on each QObject,
preventing Python object-ID reuse from applying another widget's source string.
Live language changes update existing widgets, and an application event filter
translates dialogs shown later.

Custom packs are size/type/ID/schema validated, assigned a `custom:` namespace,
staged in the destination directory, and atomically replaced only after the
staged copy reloads successfully. A pack can replace only its own qualified ID.
Unknown strings and missing translations fall back to exact English source.
Per-user language files live outside the executable and therefore survive frozen
upgrades. The frozen smoke gate confirms at least eight bundled JSON resources.

## Authenticated control plane and Pi

The external API is opt-in. Its host and every backend URL are independently
validated as IPv4/IPv6 loopback; wildcard/LAN binds are rejected. A random
per-installation bearer token of at least 256 bits is atomically stored, can be
regenerated transactionally, and can be overridden by environment. The settings
dialog writes enabled state, port, and token in one checked atomic transaction,
so a failed write preserves the previous complete configuration.

HTTP worker threads submit `ControlRequest` objects through queued Qt signals.
Only the GUI thread selects models and mutates the managed-server registry. One
switch lock serialises complete model changes. AutoTuner stops only the previous
API-managed server, waits asynchronously for its process group to exit, reuses
the model's saved profile/options, launches the replacement, and completes the
request only after `/health` returns 200. A control deadline stops and removes an
alive-but-never-ready backend before returning 504.

A proxy lease atomically snapshots backend URL, alias, and backend credential
under the switch lock. Conflicting switch/stop requests return `409 model_busy`
until in-flight requests drain, preventing time-of-check/time-of-use routing and
stream truncation. Same-model requests remain concurrent. Gateway credentials,
`X-API-Key`, Host, hop-by-hop headers, and body lengths are stripped before
proxying; a separate llama-server key is supplied only when that server was
launched with one. Launch logs redact direct key/key-file arguments. SSE uses
`HTTPResponse.read1()` plus immediate client flushes, verified with delayed
chunks.

The dependency-free Pi extension:

- reads persisted settings or validated loopback environment overrides;
- honours `AUTOTUNER_API_URL` first, then
  `AUTOTUNER_CONTROL_API_PORT`, then the saved/default port;
- fetches the live catalogue before `pi.registerProvider()`;
- implements `refreshModels` without a static `models.json` list;
- type-checks against the installed `ProviderModelConfig` contract; and
- completes a real Pi `--list-models autotuner` discovery run without a Node or
  libuv shutdown failure.

The per-OS release ZIP staging now includes `pi/autotuner.ts` and its README.

## Remaining bounds

- The API intentionally remains local-only; remote/LAN exposure requires a
  separately reviewed authenticated reverse proxy and is not enabled here.
- A conflicting model switch during active generation returns 409 instead of
  terminating that generation. Clients should retry after the stream finishes.
- Stable IDs include a normalized local path digest. They remain stable while a
  model stays at the same path on one OS; moving a GGUF or switching OS path
  conventions creates a new identity by design.
- Pi-level `reasoning_effort` is disabled because many llama.cpp builds reject
  it. AutoTuner's saved thinking/template launch settings remain authoritative.
- User-created language packs are structurally and transactionally validated;
  the user remains responsible for the grammar of their own translated values.
