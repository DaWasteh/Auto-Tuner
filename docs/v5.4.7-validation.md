b10896+ gate must stay. The same request on the still-installed **b10903**

for every build from b10896 on and names both working alternatives.

Lazy loading: the 26.8222-GiB PLE table (exact **28,800,138,240-byte** range)
had **266,240 resident bytes** at readiness on Vulkan (the same 266,240 bytes on HIP);
whole-process RSS was 15.30 GiB (Vulkan) / 15.04 GiB (HIP) at readiness.
These are point-in-time observations, not residency limits.

## Publication gates and limits

The local build precedes push. The annotated **v5.4.7** tag is created only
following successful main CI: Ruff, Python **3.10–3.14** on Windows, Ubuntu
and macOS, plus Fedora, Arch, Mint, CachyOS, Kali and Debian source tests.
The tag workflow builds native Windows x64, Linux x64 and macOS arm64 ZIPs,
smoke-tests them and launches the same generic Linux ZIP on seven distributions
before publication. Published ZIPs are then checked for architecture, executable
bits and GitHub SHA-256 digests. CI's Windows EXE is independently built with
Python 3.12 and need not match the local EXE hash.

No CUDA/Metal/iGPU inference, new-model weight inference, or universal
long-context/performance guarantee is claimed. The qwen4exp indexer-V reserve
and the MTP draft-context plan intentionally stay conservative on b10930.
Linux/macOS packaging CI is not GPU-inference validation. macOS is a community
build without Apple notarization: Finder right-click → Open / Privacy & Security
→ Open Anyway may be required.
