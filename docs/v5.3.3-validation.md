# AutoTuner v5.3.3 validation

Validation date: 2026-08-30

## Scope

This release changes adaptive performance-campaign context planning,
backend/runtime-qualified benchmark persistence, selected-model analysis, the
global HTML report, transactional reruns, and model profiles for HY4 Preview and
GLM-5.3/Flash. Validation covers the persistence migrations, estimators, GUI
planning, report accessibility, profile matching/runtime gates, cross-platform
source behavior, and the rebuilt frozen Windows application.

## Adaptive context and memory planning

Adaptive setup stores `0` as the request and recomputes the actual context for
every model × selected runtime × performance-mode job. Only Fixed context can
enable an exact real-context trial. Regression coverage exercises two models,
two independent hardware/runtime snapshots, and Safe/Throughput lanes, proving
that no context is copied across jobs.

Additional estimator gates cover:

- Qwen3.8 Flash Next IQ1_S (67.564 GiB total: 26.822 GiB read-lazy PLE plus
  40.742 GiB placement) versus Q2_K_XL (73.453 GiB total: 46.630 GiB
  placement), with the smaller quant never receiving less Safe context.
- QSA/indexer KV and context×ubatch graph buffers, every parallel slot, final
  KV/workspace guards, and a fail-closed error when fixed reservations cannot
  leave the minimum 2,048-token context.
- Dense partial placement balancing both the VRAM-side and RAM-side portions of
  layer-split KV, preventing a RAM-saturated Safe plan from collapsing below a
  faster mode.
- Conservative full-layer context accounting for fork-only HY4 Gated DSA and
  GLM-5.3-Flash KDA/DSA pools until patched runtimes expose a validated exact
  allocation formula.

## Backend/runtime persistence and analysis

HIP, Vulkan, CUDA, CPU, and other evidence is backend-qualified. A requested
concrete backend cannot consume another concrete backend's compatibility mirror;
backendless legacy evidence is accepted only when no concrete lane makes it
ambiguous. Multiple builds of one backend retain separate runtime-qualified
records. Backend-specific preferred targets survive profile-bundle export/import,
and Custom profile selection/save/clear follows the active backend.

Bounded benchmark failures are checkpointed as failed candidate records (error,
settings, and bounded log text) without promoting a Perform snapshot. A failed
job no longer aborts the rest of a bounded suite; a genuine persistence failure
still stops before the next job.

The Qt analysis dialog filters to the selected model while retaining every
Winner, Measured, and Failed candidate. Exported HTML remains global. Its
vertical metric charts use unique IDs and valid ARIA references, escape all
stored text, and preserve candidate settings and errors.

## Transactional reruns and settings durability

“Reset old measured data, then rerun all” performs one fail-closed write before
any server starts. It removes scoped exact/portable/backend/drafter evidence and
Perform snapshots, preserves user-owned Custom profiles and untargeted modes,
and never restores stale evidence after cancellation. Settings read/modify/write
operations are serialized, and each atomic replacement uses a unique same-folder
temporary file. A concurrent-writer regression verifies that unrelated sibling
updates are not lost.

## Model profiles and runtime gates

All 66 YAML profiles load successfully.

- Full GLM-5.3 shares the verified `glm-dsa`/1M-context contract with GLM-5.2.
- GLM-5.3-Flash remains a separate `glm5next` profile. It requires a patched
  runtime capability marker, documents the open llama.cpp PRs and
  multimodal/MTP/unified-KV/quantization caveats, and caps automatic context at
  262,140 pending validated full-1M runtime support.
- HY4 Preview matches `hyv4`/`hy_v4`, requires the patched architecture marker,
  and documents that the known community GGUF conversion drops native MTP.
- Qwen3.8 Flash Next requires b10666+, the first allocator version used for the
  shipped QSA graph-memory coefficients (the loader itself landed in b10660).

## Remaining bounds

- GLM-5.3-Flash and HY4 remain patched-runtime profiles, not claims of stock
  upstream llama.cpp support. Their capability markers deliberately fail closed.
- The GLM-5.3-Flash model metadata advertises 1M native context, but current
  patched-runtime evidence does not justify automatic planning above 262,140.
- Benchmark results can be compared across builds only when workload and quality
  signatures match; launch reuse remains exact-environment validated.
