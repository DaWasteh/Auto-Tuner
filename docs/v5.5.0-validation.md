Local checks: **2026-09-15**, Windows x64, Python **3.14.5**. Runtime under
test: freshly built **b10977** HIP and Vulkan trees plus the **v0.4.1**
(b10964) stable trees from the [b10977 audit](llama-b10977-audit.md); the
same binaries are hashed in [llama-b10977-server-flags.json](llama-b10977-server-flags.json).

stable release), adds the `maple.yaml` profile for DeepGrove Maple-Preview
and moves the DeepSeek-V4.1 and vision+DFlash2 gate wording to b10977.
No AutoTuner planner or GUI logic changed.

## Observed, not changed

- Maple on HIP works but is CPU-bound because `ggml-cuda` has no TQ1_0/TQ2_0
  kernels; the profile note tells users to prefer the Vulkan runtime. No
  automatic backend switch was added.
- The follow-ups recorded in [v5.4.9](v5.4.9-validation.md) (switch stops the
  old server before planning; CTRL_BREAK delivery unverified in automation)
  are unchanged.

macOS and six Linux distributions, the tag workflow's native ZIP builds and
smoke tests, digest/architecture verification of the published assets) are
the same as in [v5.4.9](v5.4.9-validation.md).
