# AutoTuner v5.4.0 validation

Validation date: 2026-09-04

## Scope

This release validates AutoTuner against exact stock llama.cpp b10797, fixes
the Qwen3.8 Flash Next Quick-suite failures by adding an MTP sidecar
preflight, replaces the oversized performance-summary message box with a
scrollable dialog, and rebuilds the tracked Windows application.

The upstream review is recorded in
[`llama-b10797-audit.md`](llama-b10797-audit.md).

## Flash Next Quick-suite failure

Evidence from the v5.3.9 run (application log and stored records, 32 lanes on
b10786 Vulkan and HIP, four performance targets x two sidecars x two builds):

```text
llama_model_load: error loading model: check_tensor_dims: tensor 'output_hc_norm.weight' not found
llama_model_load: error loading model: check_tensor_dims: tensor 'token_embd.weight' not found
```

Both community `mtp-Qwen3.8-Flash-Next-*.gguf` files declare `qwen4exp` and
contain only `blk.48.*` (plus `token_embd`/`output` in the non-shared file).
Header reads of every sibling drafter on the machine confirm the contract:
working Qwen3.6 MTP heads carry `token_embd`, `output_norm`, and `output`.

Fix: `scanner.read_gguf_metadata()` records the root (non-`blk.`) tensor names
of each header; `tuner.check_draft_model_build()` accepts the target entry and
refuses a same-architecture NextN sidecar that lacks any required root tensor,
naming the missing tensors. The GUI launch, the CLI launch, and the Quick
suite pass the target. Verified against the real files:

```text
mtp-Qwen3.8-Flash-Next-Q4_K_M.gguf        missing: output_hc_down, output_hc_norm, output_hc_up, per_layer_token_embd
mtp-Qwen3.8-Flash-Next-shared-Q4_K_M.gguf missing: output_hc_down, output_hc_norm, output_hc_up, per_layer_token_embd, token_embd
mtp-Qwen3.6-35B-A3B-NVFP4.gguf vs Qwen3.6-35B-A3B-MTP-UD_Q6_K.gguf: compatible (no false positive)
```

The metadata cache schema is bumped so previously cached headers are re-read
once and receive the new root-tensor list.

## Performance summary dialog

`QMessageBox` grew with the multi-model summary beyond the screen height and
hid the OK button. Completion and failure reports now use a scrollable,
read-only dialog capped at 75% of the available screen height and 90% of its
width; a Qt test renders a 400-line summary offscreen and asserts the cap and
a visible OK button.

## Remaining bounds

- The preflight judges sidecars by root tensors only; a sidecar with the right
  root tensors but incompatible block shapes still fails inside llama-server
  and is reported as before.
- b10797 was validated on the local Vulkan build. The b10786 Vulkan and HIP
  trees validated for v5.3.9 have since been removed from this machine; the
  b10786→b10797 range contains no HIP-specific change.
